## 4. 机会拆解

### 机会 A：AI 代码治理 Linter（实时防漂移）

**痛点**：AI 生成代码速度快但经常"跑偏"——忽略已有架构决策、引入不兼容的依赖、使用已被废弃的模式。

**买家**：使用 AI 编程工具（Claude Code/Cursor/Codex/Windsurf）的 5 人以上开发团队。

**已有替代方案**：Prelint（事后 PR 审查）、MemoryCustodian（记忆管理）、人工 Code Review。

**小产品入口**：VS Code/JetBrains 插件，在 AI 生成代码时实时比对项目 `.cursorrules`/`CLAUDE.md`/ADR 文档，标注"这里和你的架构决策不一致"。

**可验证数据**：在 3 个使用 AI 编程的开源项目中运行，统计"漏标率"和"误标率"。

**风险**：如果 Prelint 等现有工具快速迭代加入实时功能，差异化窗口会很短。另外，准确判断"代码是否漂移"本身是个难题——需要深度理解项目上下文。

### 机会 B：模型路由器 / 自动降级网关

**痛点**：GPT-5.6 有 Luna/Sol 两个端点，加上 Claude、Kimi、Gemini 等，开发者面对"什么时候用哪个模型"的选择困难。选错了要么多花钱，要么效果差。

**买家**：月 API 调用量 >100 万 Token 的开发者/团队。

**已有替代方案**：OpenRouter（手动路由）、自建模型选择逻辑。

**小产品入口**：OpenRouter 的上层封装——自动分析 prompt 复杂度 → 路由到最合适的模型 → 失败时自动升级。提供"成本 vs 质量"滑块。

**可验证数据**：跑 100 个真实 prompt 对比"全用 Sol" vs "智能路由"的成本差异。

**风险**：OpenRouter 如果自己做这个功能，小团队很难竞争。GPT-5.6 本身如果继续降价，路由的价值也会降低。

## 5. 反向视角

1. **如果"AI 代码治理"是伪需求** — 开发者可能更倾向于"让 AI 变得更好"而非"增加一个审查层"。当 GPT-6 出来时，代码漂移问题可能大幅减少，治理工具的价值随之缩水。历史上，代码 Linter 的采用率本身就不高。

2. **如果 KOSPI 崩盘只是韩国特有现象** — 韩国散户杠杆率（超过 GDP 的 30%）在全球范围内是极端的。美国/中国市场结构不同，可能不会出现类似的连锁反应。所谓"金丝雀"可能只是一只自己摔死的鸟。

3. **如果 OpenAI 的收入增长不可持续** — 7 月超过 Q2 可能是因为 GPT-5.6 发布带来的"尝鲜效应"，而非持续性增长。如果用户发现 Luna 虽然便宜但不够好用，可能回流到 Claude/Gemini。

4. **如果模型价格战让所有 AI 产品都受益** — 反向思考：更便宜的 API 可能降低所有 AI 产品的成本，扩大市场总盘子，而非挤压中间层。历史上云计算降价也促进了 SaaS 繁荣。
