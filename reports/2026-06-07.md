## 今日主判断

**本周最值得关注的变化不是单个事件，而是一个逐渐成形的模式：AI 不仅在帮人类写代码，它已经开始帮 AI 公司设计下一代 AI 芯片和训练更好的 AI。**

Anthropic 6月4日公布，Claude 写了自身 80%+ 的生产代码；微软 6月2日发布 Majorana 2 量子芯片，由 AI agent（Microsoft Discovery）协助设计。两件事相隔仅两天，指向同一个方向——AI 正在从"被开发的工具"变成"参与下一代工具开发的协作者"。这个闭环一旦转起来，迭代速度会远超人类预期。

与此同时，周五（6月5日）全球资产暴跌——纳指跌近2%、费城半导体重挫、博通跌12.59%、黄金跌超100美元。导火索是强劲非农数据推升美联储加息预期。这提供了一个对照：**市场在定价"传统宏观风险"，但可能低估了 AI 加速迭代对竞争格局的重塑速度。**

## 今日 Top 3 信号

### 1. Anthropic：Claude 写了自身 80% 生产代码，工程产出 8 倍增长

**白话说：**
Anthropic 公开了内部数据：到 2026 年 5 月，合并到生产代码库的代码中超过 80% 由 Claude 编写（2025 年初仅个位数百分比）。工程师每天合并的代码量是 2024 年的 8 倍。开放任务成功率从 26% 飙升到 76%。最极端案例：Claude 在 2026 年 4 月独立完成 800+ 个修复，将某类 API 错误降低了 1000 倍——人类工程师估计需要 4 年。

**证据：**
- Anthropic 官方报告（anthropic.com/institute/recursive-self-improvement）：6 月 4 日发布，包含四个阶段的演变数据
- Tom's Hardware：Anthropic 警告"递归自我改进"可能让人类失去对 AI 的控制，呼吁建立暂停机制
- The Next Web：数据从"低个位数"涨到 80%+，仅用了 15 个月

**对你的启发：**
这是产品机会的强烈信号：开发者需要的不再是"怎么写代码"，而是"怎么管理、审计、测试 AI 写的代码"。代码审计、AI 代码覆盖率追踪、AI 生成代码的安全测试——这三个方向的需求曲线会陡峭上升。

### 3. Microsoft Miasma 蠕虫感染 73 个官方 GitHub 仓库

**白话说：**
自复制供应链攻击 Miasma 蔓延到微软，感染了 Azure、Azure-Samples、Microsoft、MicrosoftDocs 四个组织的 73 个仓库。GitHub 已禁用相关仓库访问。这不是第一次供应链攻击，但这是第一次同时击中微软旗下四个核心组织的攻击，规模空前。

**证据：**
- OpenSourceMalware 通报 + blog.ibvl.in 报道（6 月 6 日）
- 涉及 Azure、Azure-Samples、Microsoft、MicrosoftDocs 四个 GitHub 组织
- GitHub 已采取行动禁用访问
- 一周前同样的事件影响了 Mantine-datatable 等 NPM 包（6 月 6 日报告已记录）

**对你的启发：**
依赖开源组件的项目需要建立依赖安全监控机制——不仅监控漏洞，还要监控维护者账户状态、仓库访问权限变更。手动检查不可行，自动化监控是刚需。这也呼应了信号 1 中的"AI 代码审计"方向。

## 机会拆解

### 机会：AI 代码安全审计工具

**痛点：**
AI 写的代码占比从 5% 涨到 80%，但代码审查工作量没有同步增长。工程师不审查 AI 写的每一行代码（也做不到）。安全隐患在累积。

**买家：**
- 使用 Cursor / Claude Code / Copilot 的中型工程团队负责人（10-100 人）
- 有合规要求的金融/医疗科技公司的 CTO
- 开源项目维护者（担心贡献者用 AI 生成的代码引入漏洞）

**已有替代方案：**
- SonarQube、Snyk（传统 SAST，不针对 AI 生成代码特征）
- GitHub Code Scanning（通用，没有 AI 代码专项规则）
- 人工 Code Review（速度跟不上 AI 生成速度，已不现实）

**小产品入口：**
一个 CLI 工具 + GitHub Action：扫描 PR 中被标记为 AI 生成的代码段 → 运行 AI 代码特有的安全检查（幻觉注入、不当错误处理、过时 API 调用、依赖风险）→ 输出风险评分 + 修复建议。

**可验证数据：**
- 一周内：分析 3 个知名开源项目的 AI 生成 PR，手动标注安全问题，与工具扫描结果对比，计算检出率
- 发布分析报告到 Hacker News / Reddit r/programming，看讨论量

**风险：**
- 大厂可能快速跟进（GitHub 已有 Code Scanning，加入 AI 专项规则是自然的下一步）
- 用户付费意愿待验证——"AI 代码安全"目前还不是 CTO 的预算项
- 技术门槛不高，容易被复制

## 反向视角

**如果"AI 造 AI 加速"这个判断不成立：**

1. **只是一个公司的数据，不代表行业趋势。** Anthropic 公布的 80% 数字可能选择性展示——最理想的项目、最配合的工程师。其他公司的 AI 代码占比可能远低于此。

2. **80% 是数量不是质量。** 800 个 API 修复听起来很震撼，但"减少错误 1000 倍"可能是从少量错误减到更少的统计放大效应。人类工程师做同样的事可能需要 4 年，但也可能只需要 4 天——这取决于问题类型。

3. **递归自我改进有天花板。** Claude 写 Claude 的代码，但真正的架构突破、新算法设计可能仍需要人类。AI 擅长在已知框架内优化，不擅长推翻框架本身。

4. **Anthropic 有动机夸大。** 这是一家需要持续融资的 AI 公司。公布"AI 已经在造自己"的数据，有利于估值叙事和吸引人才。需要独立验证。

5. **（投资）周五暴跌可能不是买入机会。** 如果非农数据标志着美国经济过热 + 通胀顽固，加息可能比市场目前定价的更激进、持续更久。在当前估值水平下，纳指仍有下跌空间。

## 今天不要追

- **不追 1：不要因为 Anthropic 的报告就立刻押注"AI 代码审计"创业。** 先验证：有多少团队真正在担心 AI 代码安全问题？他们现在怎么解决？愿不愿意为专项工具付费？这三个问题的答案可能让人失望。
- **不追 2：不要在 WWDC 前押注 Apple 概念股。** WWDC 是软件发布会，不是硬件发布会。iOS 27 / Siri AI 更新可能很精彩，但不一定转化为短期股价催化剂。历史数据表明 WWDC 后 Apple 股价短期涨跌各半。
- **不追 3：不要因为周五暴跌就抄底半导体。** 费城半导体指数中，博通 -12.59% 是因为 AI 收入指引不及预期（基本面问题），美光 -6% 是因为存储周期担忧。这些不全是"宏观错杀"，有些是估值回归。等尘埃落定。
